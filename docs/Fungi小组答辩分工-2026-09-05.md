## 组员 A —— 同意流与跨主机协作

**开场白（30 秒）**
"我演示的是 Fungi 最核心的机制：跨主机的同意流。Fungi 里所有请求——包括一个主机上的 AI 想读另一台主机的文件——都走统一的消息信封，由对方的用户在 WebUI 卡片上裁决。"

**演示脚本**
1. 两台真机组房间（主机 A 起房，主机 B 用 Token 加入）。
2. 在 A 的会话里让 AI 对 B 的 homes 目录做一次文件操作 → B 的 WebUI 弹出 consent 卡。
3. 展示卡片的四个选项：允许 / 禁止 / 自定义输入 / 始终允许——选"自定义输入"，回复一句条件性同意。
4. 讲一句关键设计："同意就是一条普通消息，没有 Redis 之类的协调服务；断线重连后未决卡片会重放，不丢。"

**必须吃透的 3 个概念**
- **ask envelope**：所有"请求-应答"统一成消息信封走同一条投递链，inquire（提问）和 confirm（裁决）不搞两套机制。
- **at-least-once + 去重**：消息可能重发，但消息 id 去重，保证不重复处理。
- **重放**：心跳机制里带着未决卡片，B 断网重连后还能看到没裁决的卡片。

**可能被问**
- "为什么要用户裁决？"→ AI 有原生工具权限，但跨主机操作的是**对方的地盘**，属主用户的同意是安全边界。
- "如果 B 一直不回复？"→ 请求方阻塞等待，有超时机制，不会永久卡死。

## 组员 B —— GUI 启动器与托盘体验

**开场白（30 秒）**
"我演示的是普通用户看到的 Fungi：从双击启动到进房间、到关窗后台驻留的全流程。"

**演示脚本**
1. `python start.py`：展示启动器界面——发起房间 / 加入房间 / 打开 WebUI / 模型配置 / 帮助。
2. **Token 自定义**：在发起按钮上方输入框改 Token（字母数字，1-64 位）→ 按回车生效；强调"运行中改完回车立即热更新，老朋友要用新 Token 重进"——这是为了保证房间不被陌生人蹭进。
3. 组好房间后**关窗** → 弹提示"Fungi 已转入托盘"，房间继续跑；托盘图标右键菜单演示。
4. **单实例**：再双击一次启动器 → 不会开第二个，而是把已运行的主界面唤到前台（QLocalServer IPC）。
5. 切一下暗色主题。

**必须吃透的 3 个概念**
- **托盘驻留**：关窗 ≠ 退出；房间是服务，得常驻；toast 提示保持极简文本。
- **单实例 IPC**：用 QLocalServer 命名管道，第二个进程发现已有实例就发一条 `show` 消息然后退出。
- **热更新 Token**：运行中改 Token 即时生效，安全上等于"换锁"，旧 Token 立即失效。

**可能被问**
- "为什么关窗不退出？"→ 因为 server 角色承载整个房间的中转，关了全房间断线。
- "Qt 用的什么？"→ PyQt5 + qfluentwidgets，fluent 风格，零额外重依赖。

## 组员 C —— 文件空间与安全 + 测试与发行

**开场白（30 秒）**
"我讲两块：一是 Fungi 的文件空间怎么在'AI 自由协作'和'用户地盘神圣'之间划边界；二是项目的质量保障和发行流程。"

**演示脚本**
1. 打开文档里的权限表讲三种目录：
   - `public/`——所有通讯 clone 自由读写，协作区；
   - `homes/<host>/`——属主写自己家自由，**别人读写都要属主用户同意**；
   - `sessions/`——clone 完全摸不到，只能经本机 clone 代理给用户看。
2. 强调安全实现："路径守卫在 **server 端强制**——前缀校验、拒绝 `..` 和绝对路径逃逸，不依赖客户端自觉。" 可现场让 AI 尝试越界路径看被拒。
3. send_file：字节流在 hub 暂存，接收方用户同意后落进 `inbox/<来源主机>/`——来源可追溯。
4. 质量保障：`scripts/check.ps1`（ruff + pytest 全量门禁）、267 个测试、GitHub Actions CI（push 即跑 pytest 硬门禁）、tag 触发自动打 release（v0.1.0 已发布）。

**必须吃透的 3 个概念**
- **服务端强制 vs 客户端自觉**：安全边界放在 server，因为客户端（AI clone）不可信。
- **最小权限三分区**：协作要开放（public），私产要保护（homes），内部状态要隔离（sessions）。
- **CI/CD**：CI 是每次 push 的 pytest 门禁；CD 是打 tag 自动出源码 zip 和 Release，config.json 不入档。

**可能被问**
- "homes 里 AI 自己写自己家也要同意吗？"→ 属主 clone 写自己家不需要，防的是**别的**主机。
- "测试怎么跑？"→ 本地 `powershell -File scripts/check.ps1`；CI 上 Windows runner 跑 pytest，无 Qt 环境自动跳过 Qt 用例。

## 你 —— 项目定位与总体架构（突出你的部分）

**开场白（1 分钟，把分量立住）**
"这个项目从零到发布由我主导设计与实现：包括三代 harness 的演进设计（Psi → YESIR → Fungi）、TriLayer 编排、星型拓扑网络协议、全部前后端代码、267 个测试和 CI/CD。下面我讲清楚它是什么、为什么这样设计。"

**讲稿要点**
1. **动机**：一个进程里的 Orchestrator 再强也只在一台机器上。Fungi 把 Orchestrator 撒到 LAN 每台主机，让它们彼此成为工具。
2. **架构图**（README 里有）：server hub 承载 roster / relay / pending-asks / 数据存储；每主机一个本机 clone 对用户，一个通讯 clone 对远端；跨主机流量全部经 server 投递。
3. **克制**：消息即 envelope、无协调设施、工具白名单（通讯 clone 拿不到原生 bash/read/write）——引用 Around 教训："先写 spec 再动手"。
4. 现场组一次真房间，把话筒交给 A。

**你的收尾（全场总结）**
"我的组员分别验证和演示了同意流、桌面体验、文件安全与发行流程。整个系统目前 267 个测试全绿，v0.1.0 已发布。"
